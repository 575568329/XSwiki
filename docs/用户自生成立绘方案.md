# 用户自生成立绘方案（插件内一键生成）

> 2026-10-23 调研定案，同日审阅修订（存储/CORS 架构、展示优先级、通道口径、并发与离线边界）。
> 背景：作者端批量画 795 人不现实（第一批 6 人走了完整的档案提取+盲审流程），改为**让插件用户对任意角色一键生成立绘**——反正有免费生成通道。

## 一、别人怎么做的（调研结论）

### SillyTavern（行业标准，直接可抄的范式）
- 内置 Stable-Diffusion 扩展把 **Pollinations 列为一等免费源**（零 key 零配置），另有本地 SD、NovelAI、自定义 key 等后端可选——免费兜底 + 进阶自选的双层结构
- **FREE_EXTENDED 模式**：先用 LLM 把角色卡描述扩写成绘画标签再出图（提示词增强开关）
- UX：角色卡一键生成头像 → 不满意重 roll → prompt 模板用户可编辑
- 启示：读者/玩家侧工具的标准做法就是"免费无Key源兜底 + 用户可选升级"

### Pollinations 现状（本项目已多次实测）
- 匿名档直连可用：`GET image.pollinations.ai/prompt/{prompt}?width=768&height=1024&nologo=true`，2026-10-23 实测 1.2s 返回、零 key；免费模型为 sana（质量中等，小图卡片够用，脸的精度弱）
- 语气注意：prompt 用简洁标签式比长段落稳定

### Legado 生态（openhanako-legado）
- "AI 画像"走用户自配 LLM 路线（需用户配置模型）——证明"用户自带 key"也是读者工具的通行做法，可作进阶选项

## 二、我们的独有优势（为什么我们能做得比他们好）

1. **结构化人物数据现成**：793 人卡片自带 visualLine、stages[]（分阶段 visual 描述）、identity、cultivation——prompt 组装的原材料比 SillyTavern 的自由文本角色卡质量高得多
2. **着装档案沉淀**：核心角色有精确到章节号的分年龄档案（analysis/着装档案/），可做"高保真模式"
3. **portrait 挂载机制现成**：`portrait` 字段有值才显示、无值走印章降级（CharacterCard 已实现），用户生成的图直接进这个通道
4. **免费通道已实测**：Pollinations（读者零门槛，本项目多次直连成功）；本地 doubao2api（作者与进阶用户跑，质量第一梯队）。另有用户自带 key 通道（SiliconFlow/智谱，注册制，进阶选项不算免费）

## 三、功能设计

### 交互
- 人物详情页按钮按角色分两种：
  - 无官方图 → **✨ 生成立绘**
  - 已有官方图 → **🎨 自制立绘（官方版可用）**——明确不会顶掉官方图
- 点击 → 组装 prompt → 弹窗（见 §三·b）→ 出图 → 预览 → **保存**（存本地，卡片立即显示）/ **换一张**（换 seed）
- 已生成过的人物按钮变"重新生成"，图可删除（回到原有展示：官方图或印章）

### Prompt 组装（卡片数据 → 标签式）
`[类型风格块] + visualLine + 最新成年 stage.visual + 一句话场景`，标签式短句（sana 对长段落不稳定）。
人物形象**优先取成年阶段**（stages 末段 visual；着装档案有成年段则更准），与 dbst 管线的"能成年就成年"原则一致。
例（李清虹·成年）：`国风厚涂插画，全身立绘，青白羽衣女修，杏眼柳眉，黑发飘拂，手持红缨长枪，周身紫雷，乌云荒野上空，冷色调`（约 60~100 字）
⚠️ 组装必须查证兵器与身份词（她是枪修不是剑修），避免示例级硬伤。

### 设置页新增
- 画风预设：国风厚涂（默认）/ 水墨 / 动漫 / 写实剧照
- 比例：2:3（默认）/ 1:1；张数：1（默认）/ 2 / 4
- 进阶（折叠）：
  - 自带 key 通道：SiliconFlow / 智谱 API key（注册制，走高质量模型）
  - 本地 doubao2api 地址（http://127.0.0.1:9090，作者与折腾党用，质量最高）
  - 生成通道自动降级顺序：doubao2api（若可达）→ 用户 key → Pollinations 免费

### 存储（⚠️ 实现硬约束）
- **禁止 localStorage/IndexedDB 存图**：uTools 插件升级会清 webview 存储（本项目已踩过：上一版立绘功能即因此删除存储读写）。图片必须落真实文件（`~/.utools-novel-characters/portraits/{bookId}/{cid}-{seed}.png`）或 uTools.db；localStorage 只放轻量偏好（风格/比例/剧透确认记录）
- 卡片展示优先级：**官方随书图 > 用户自制图 > 印章**。用户保存自制图时若该角色已有官方图，提示"官方立绘仍在，可随时切回"
- 每角色保留最近 N 张（默认 20），超限淘汰最旧

### 防剧透与导出
- 防剧透联动：角色所处章节 > 用户阅读进度时，生成按钮提示"该角色后期形象含剧透"由用户确认（记住选择）
- "导出我的立绘"改为**导出本地备份**（zip：images/{id}.png + 生成参数 json）；是否收录进官方包由作者在仓库侧按盲审标准另行决定，插件内不做"回馈作者"承诺，避免质量期待落差

### 质量定位（明确预期）
- Pollinations 免费档 = 读者自娱 + 占位，脸和道具精度有限（重 roll 抽卡）
- 高保真（着装档案级）仍走作者端 dbst 管线；插件内按钮对核心角色可附"获取官方立绘版"说明

## 三·b、弹窗交互设计（2026-10-23，借鉴成熟项目范式）

### 借鉴来源 → 采纳机制

| 来源 | 成熟机制 | 我们的采纳 |
|---|---|---|
| SillyTavern SD 扩展 | 按用途分生成模式（角色头像/背景/自由），prompt 从角色卡**自动组装**；FREE_EXTENDED=LLM 扩写标签；重型参数（源/模型/步数/采样器）全在设置面板，**流程内只留一键** | 重型配置进设置页和"高级"折叠；弹窗内 prompt 自动预填可编辑 |
| SillyTavern | 负向提示词可选、分辨率记忆复用、pollinations_enhance 开关 | 进阶折叠里：负向预填、seed 记忆 |
| NovelAI | 候选图网格、seed 锁定/骰子、历史条 | 张数 1/2/4 候选格 + seed 骰子 + 底部历史缩略条 |
| Midjourney | 4 候选 → 选优 → 变体 | 候选点击选中 → 保存为立绘 / 以此重生成 |
| 即梦/豆包 web | 风格预设 chips、比例 chips、"做同款" | 风格/比例 chips；历史图"复用参数" |

### 弹窗布局

```
┌────────────────────────────────────┐
│ ✨ 生成立绘 · 李清虹            ✕  │
│                                    │
│ 风格  (国风厚涂)(水墨)(动漫)(剧照)  │
│ 比例  (2:3)(1:1)   张数 (1)(2)(4)  │
│ ┌────────────────────────────────┐ │
│ │ 提示词（预填，可编辑）           │ │
│ │ 国风厚涂插画，全身立绘，青白羽衣… │ │
│ └────────────────────────────────┘ │
│ (已修改·还原⟲)      ▸ 高级选项      │
│                                    │
│         [ ✨ 生 成 ]  [取消]       │
│ ──────────────────────────────────│
│ 结果区：骨架图… → 候选格(1/2/4)    │
│   ☑选中 → [保存为立绘] [以此重生成] │
│ ──────────────────────────────────│
│ 历史：(□)(□)(□)(□)… 本机20条       │
└────────────────────────────────────┘
```

### 交互状态与细节

1. **打开即预填**：prompt = 风格块（chips 决定）+ 人物（visualLine + 最新成年 stage.visual）+ 场景占位（"雪中练枪…"，用户自填）。用户编辑后显示"已修改"徽标 + 一键还原。
2. **生成中**：按钮变"取消"，结果区显示张数对应的骨架占位；pollinations 无进度条，用已等待秒数提示。
3. **候选与保存**：完成 → 候选格；点击选中（高亮）→ 主按钮变"保存为立绘"；保存 = 写本地文件 → 卡片立即生效 → toast。次按钮"以此重生成"（锁定该图 seed 微调 prompt）。
4. **历史条**：本机该角色最近 20 张，点击重看/重存/删除/"复用参数"（把该图的风种/seed/prompt 回填表单，即"做同款"）。
5. **高级折叠**（默认收起）：seed（骰子/锁定上次）、负向提示词（预填 `水印, 文字, 多余手指, 低质量`）、生成通道（自动降级：doubao2api→用户 key→免费直连，可手动锁定）。
6. **防剧透**：角色 lastChapter > 用户阅读进度 → 生成前一次性确认"该角色形象含剧透"，记住选择。
7. **失败与降级**：单张失败自动重试 1 次；整批失败给出通道建议（"可到设置改用自带 key 通道"）。
8. **并发纪律**：候选按**串行队列**生成（完成一张亮一张），张与张间隔 ≥2s——匿名档并发连发大概率 429。默认张数 1。
9. **离线态**：preload 探测网络不可达时按钮置灰 + "需要网络连接"提示，而非点击后报错。

## 三·c、实现架构（⚠️ 硬约束）

- **所有外部图片请求在 preload（Node 侧）发出**：https 图直接 fetch 回 base64 走 IPC 传渲染层——渲染层直连会撞 CORS/画布污染，PoC 第一天就会卡住；Node 侧还顺带统一了三条通道的调用（pollinations/SiliconFlow/doubao2api 同一套 IPC 接口 `generatePortrait(params)`）
- 渲染层只负责：组装参数 → IPC → 展示候选 → 保存（IPC 落盘用户目录）→ 读缓存展示
- 图片文件统一 PNG（与 `portrait: data/images/{id}.png` 的官方机制对齐），尺寸 1024 长边（官方首批实测该规格）

## 四、合规与内容边界

- 用户可自由编辑 prompt：生成内容由用户负责，插件预填文本均为作品设定类安全内容；pollinations 自身有内容过滤
- 不提供真实人物/名人肖像的引导词；角色形象版权归原作，插件定位为"阅读辅助的自娱生成"，导出仅限本地备份
