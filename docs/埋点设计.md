# 埋点设计（小说Wiki × ObjectConsole）

> 2026-10-29 立项。回答三个问题：插件要不要数据库？数据存哪？埋点怎么做、后台在哪看？
> 结论：**插件本体不需要数据库；埋点地基已 100% 存在（tracker-server + ObjectConsole），缺的只是插件端一个 ~100 行的 tracker 和看板里一个项目配置。**

---

## 一、三个问题的直接回答

**1. 需要数据库吗？——插件本体不需要，埋点后台不需要"数据库软件"。**
- 书数据/立绘：JSON 文件（内置 + 热更新），早就定案，向量库已被否决删除。
- 用户小状态（防剧透/进度/偏好）：`utools.dbStorage`（≤1MB/条，跟随 uTools 账号同步）。
- 埋点存储：复用已有 tracker-server 的追加写 JSON 文件。个人插件量级（万级事件/月）单文件 JSONL 完全够；真到瓶颈再换 SQLite（单文件零运维），采集协议不用变。

**2. 数据存 uTools 还是发服务器？——分层，不是二选一。**

| 数据 | 存哪 | 进你服务器？ |
|---|---|---|
| 书数据、立绘 | 插件内置 + 用户目录缓存 | 否（热更新只是**下发**） |
| 用户偏好/进度/统计开关 | `utools.dbStorage`（账号同步） | **否，你在后台看不到**（这是 uTools 账号体系内的 KV） |
| 热更新缓存 | `~/.utools-novel-characters/` | 否 |
| **埋点事件** | —— | **是，必须上报集中存储**（要"后台能看到"就只能发服务器） |

**3. 埋点做了吗？——零。** 全仓 grep 无任何上报/统计代码，插件仅有的网络请求是数据加载和热更新。但复用成本极低，见下。

## 三、插件端 tracker 设计

**接入点**：`plugin/preload.js` 暴露 `track(type, data)`，UI 在关键动作处调一行。批量缓冲（10 条或 30 秒 flush），`utools.onPluginOut` 时强制 flush；失败静默、内存队列封顶 200 条丢弃——**埋点永不影响功能**。

**配置**：`plugin/config.json` 加 `statsServer` 字段（留空 = 埋点关闭），与 `dataServer` 同模式——**可与热更新完全解耦独立上线**（9420 埋点首发就开、8300 热更新留空，互不牵连）。dev 联调指向 `127.0.0.1:9420` 的 dev 桶。

**事件表（最小集，5 个）**：

| t | 含义 | d 字段 | 用途 |
|---|---|---|---|
| `pe` | 插件启动 | `{v: 插件版本}` | 活跃用户、留存、版本分布 |
| `bv` | 进入某书 | `{b: bookId}` | 书目热度（加书决策依据） |
| `tv` | 切 Tab | `{b, tab}` | 功能使用率（哪个 Tab 是主力） |
| `cv` | 打开人物卡 | `{b, c: charId}` | 热门人物榜、内容覆盖度 |
| `se` | 搜索 | `{b, n: 命中数}` | **只记命中数不记关键词**（见 §五隐私）；命中数为 0 的比例 = 搜索质量指标 |
| `uc` | 热更新检查 | `{r: updated/etag/ttl/offline/net-xxx}` | 服务器健康度运维指标 |

**匿名 ID**：本地随机 ID 存 `utools.dbStorage`（首次生成）。**不调用 `utools.getUser()`**，不采集任何 uTools 账号信息。

1. 项目注册：Projects 页加 `novel-wiki` 项目（通用组件开箱即用：日趋势、事件类型分布、事件表、活跃用户）。

## 五、隐私与合规（PIPL / 市场审核）

- **采集声明**：插件 description 加一句"收集匿名使用统计（不含搜索内容与浏览内容），可在设置中关闭"——上架审核对有隐私声明的插件更友好。
- **默认开 or 默认关**：两案。**A. 默认开 + 声明 + 设置可关**（行业惯例，数据量大，"匿名+不含内容"前提下 PIPL 风险低，建议）；B. 默认关 + 引导开启（合规最稳，数据量小）。
- **红线**（写死在 tracker 里）：不记搜索词明文、不记人物名/浏览内容、不采账号/硬件指纹、事件里不进任何用户输入原文。charId/bookId 是公共内容 ID，可记。
- **关闭即物理断**：`statsServer` 留空或开关关闭时，tracker 不初始化、零请求（不是"发了再删"）。
