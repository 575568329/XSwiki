## 方案 A：doubao2api（GitHub 主推）✅ 2026-10-23 已实测跑通

**推荐仓库：[SeiShonagon520/doubao2api](https://github.com/SeiShonagon520/doubao2api)**（2026-10-15 更新，专治旧版接口失效与反爬；另 [wangchuxiaoji-oss/doubao2api](https://github.com/wangchuxiaoji-oss/doubao2api) 为原始版）。

**本机部署**：`tools/doubao2api/`（venv 用 Python 3.12，Playwright Chromium 1.64.1 走 npmmirror 镜像）。启动 `.venv/Scripts/python -m doubao2api`，端口 9090；登录态持久化在 `~/.doubao_browser`，重启服务不掉登录。登录推荐走管理页 [http://127.0.0.1:9090/admin](http://127.0.0.1:9090/admin) 的扫码面板（本项目已打补丁：二维码过期自动刷新、手机端确认失败自动重试≤5次，免去"贴出来的码过期"问题）。

**实测记录**（李清虹测试图在 `analysis/生图测试/`）：
- 文生图 `POST /v1/images/generations`：白衣持枪全身立绘 12.4s，红缨枪/玉簪/革带全对，脸部高细节，864x1152 实际出图约 2016x2688
- 图生图 `POST /v1/images/edits`：定妆图做参考图 + 雪中练枪场景 17.6s，**人物一致性成立**（脸/发型/服饰/武器延续），场景氛围到位
- 坑①：Windows curl 直接 `-d` 传中文 JSON 会编码损坏 → 必须写 UTF-8 文件 `--data-binary @file`
- 坑②：参考图 base64 过大（2.4MB）会报豆包 `params invalid` → 参考图压到 ~100KB/1024px 再传
- **水印已解决**：请求带 `"response_format":"b64_json"` 直接拿图，再跑 `tools/doubao2api/remove_wm.py` 去右下角"豆包AI生成"水印（`--mode patch` 羽化覆盖，无痕；`--mode crop` 裁底部条带保底）

### 水印去除调研结论（2026-10-23 实测）

免费版无官方开关（关水印是会员功能，作品预览页"水印设置"开关）。技术路径上：
- 水印由字节 ImageX CDN 的 `~tplv-*-cgen_lwm3` 模板实时叠加，URL 签名绑定完整路径，去模板后缀 403；
- 油猴脚本 [Qalxry/doubao-no-watermark](https://github.com/Qalxry/doubao-no-watermark) 的"API 直链"模式依赖新版网页端 `image_ori_raw` 等无水印字段，而 doubao2api 走的这条 SSE 接口里 `preview_img` 与 `image_ori` **字节级相同**（都是右下水印图），重叠合并方案在此 schema 下不可用；
- "预览图水印在左上、下载图在右下互补合并"的原理成立但前提是两个变体都存在——当前接口拿不到；
- 落地方案：`remove_wm.py`（Pillow，doubao2api venv 自带）——patch 模式取水印区正上方同尺寸块+36px 羽化边缘覆盖，plain 背景无痕、雪地等复杂纹理也已验证无痕；批量：`python remove_wm.py <目录>`；
- 合规提醒：AI 生成内容标识是平台合规特性，去水印后的图仅用于个人插件展示；若公开传播（发布到平台/商用）建议保留 AI 生成标识。
- doubao2api 已打相关补丁：`client.py`/`browser_client.py` 增加 `find_clean_image_url` + `clean_url`/`preview_url` 字段提取（新 schema 若出现无水印直链可自动利用），`unified_server.py` 支持 `response_format=b64_json`。

原理：Playwright 驱动本地浏览器登录豆包网页版，对外暴露 OpenAI 兼容 API。底层是豆包的 Seedream 生图模型——中文理解和国风插画质量显著优于 CogView/Pollinations 免费档，是目前免费渠道里立绘质量的第一梯队。

关键能力：
- `POST /v1/images/generations` 文生图 + `POST /v1/images/edits` **图生图（支持参考图 base64/URL）**——先出一张满意的人物定妆图，之后所有场景图都拿它当参考图，解决同人一致性（比换 seed 重试可靠得多）
- Windows 一键：`launcher.bat` 装环境→弹浏览器→豆包 App 扫码→`http://127.0.0.1:9090/admin` 控制台
- 即用即焚（对话记录自动删）、滑块验证码自动求解、多账号池额度轮换
- 附带免费识图（glm-4.5v 质检通道的备用替代）

代价与风险：
- 占一个常驻浏览器（内存几百 MB）；日生成次数受豆包网页版额度限制（个人账号图片额度足够插画量级使用）
- 逆向方案，豆包改版可能临时失效——选维护活跃的 fork，失效就换
- 用自己的账号，量级控制在插画用途无封号风险，但别拿去并发商用

## 方案 B：魔搭 ModelScope API-Inference（官方免费额度）

[魔搭社区](https://www.modelscope.cn/docs/ModelScope模型接入流程概览) 注册即送 **每天 2000 次** API 调用（全模型合计），含 Qwen-Image / Qwen-Image-Edit / FLUX 等文生图模型，OpenAI 风格 REST + 现成 Python/Node SDK。

- 优点：官方渠道稳定、国内直连、额度大（795 人全员出图量级也扛得住）、Qwen-Image 对中文服饰/器物词汇理解好
- 一致性：Qwen-Image-Edit 可"改图"（换装/换姿势保持人脸），配合方案 A 的定妆图可做精修
- 封装参考：[LAVARONG/ImageForge](https://github.com/LAVARONG/ImageForge)（多 key 负载均衡的本地生图台）
- 注意：额度有平台限流波动，有用户反馈实际不足 2000；跑批量时加断点续传（旧管线已有）

## 方案 C：Pollinations.AI（零门槛兜底）

完全免 key 的公开生图 API，`GET https://image.pollinations.ai/prompt/{prompt}?width=832&height=1216` 直接回图。**本机实测（2026-10-23）**：直连成功，8~12s/张，全身构图正确，但有三个硬伤：免费档模型列表只剩 `sana`（flux 已要 token）、右下角有 pollinations 水印、脸部细节糊+道具易翻车（"手持长枪"生成了扫帚）。

定位：草稿/占位/批量试提示词用，不作为正式立绘来源。

## 与现有管线的衔接

`skills/novel-characters-db/scripts/` 三件套可全部复用，只换生成端：

1. `gen-portrait-prompts.mjs`（画像卡→三层提示词：统一基调+人物锚+场景段）——不动
2. `gen-images.mjs`（原 CogView 端点）——改造点：
   - 方案 A：baseURL 换 `http://127.0.0.1:9090/v1`（doubao2api），`/v1/images/generations`，模型名按其文档填；定妆图通过 `/v1/images/edits` 带参考图
   - 方案 B：baseURL 换魔搭端点 + 用户的 ModelScope token
3. `qa-vision.mjs`（glm-4.5v base64 直传评分+<7 分重试）——不动，质检端与生成端解耦

推荐流程：**A 出定妆图（人工挑）→ A/B 图生图批量场景图 → qa-vision 自动质检**。三层提示词里的人物锚段天然就是参考图无法覆盖时的文字兜底。

## 排除项备查

- **本地 SDXL/ComfyUI/InstantID/LoRA 训练**：无 NVIDIA 独显，CPU 出一张图按小时计，排除（将来有 GPU 可走 InstantID 保脸）
- **智谱 CogView-3-Flash**：免费但 10-22 实测质量已让用户不满意，仅作兜底
- **Gemini（Nano Banana）**：一致性和质量都顶级，AI Studio 有免费档，但国内需梯子+谷歌账号，作为有代理时的加分项
- **gpt4free 各图像源**：2025 底起基本失效（Umar151515/g4fpro 已标注 NOT WORKING）
- **uTools 图像生成**：2026-10-23 复测仍"账户能量不足"
