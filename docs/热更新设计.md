# 数据热更新设计（不发版加书）

> 目标：新增小说/更新人物数据只改服务器文件，插件不发版；运行时零服务器压力（除低频版本检查）；断网完全可用。

## 一、协议：manifest + ETag + sha256

```
GET {SERVER}/manifest.json            ← 唯一的常规请求（~500B，ETag 命中则 304 空响应体）
{
  "version": 20261022180000,          // 服务器时间戳，全局递增
  "books": [
    { "id":"xuanjianxianzu", "file":"xuanjianxianzu.json",
      "title":"玄鉴仙族", "version":1, "size":1440159, "sha256":"ab12…" }
  ]
}
GET {SERVER}/{file}                   ← 仅当本地缺失或 sha256 不匹配时下载
```

- 数据文件按内容寻址（`?v=` 查询串），可长缓存
- manifest 带 `Cache-Control: no-cache` + ETag（文件 mtime+size 哈希）

## 二、客户端状态机（preload，Node 环境）

```
onPluginEnter / 手动"检查更新"
  └─ TTL 检查（默认 30min 内跳过；手动不受限）
      └─ GET manifest（带 If-None-Match）
          ├─ 304 / 网络失败 → 静默用本地，无任何提示
          └─ 200 → 逐书比对 sha256
              ├─ 本地没有/哈希变 → 下载到 {home}/.utools-novel-characters/（tmp+rename 原子写）
              └─ 全一致 → 只记 lastCheck
加载顺序：缓存目录文件 > 插件内置 data/（内置=首装快照，永不删除，兜底）
```

- **所有查询（搜索/人物卡/筛选）100% 内存本地**，不发任何请求
- 断网/服务器挂：TTL 内根本不请求；TTL 外请求失败静默降级
- 浏览器预览模式：用 Cache API 替代文件缓存（同协议）

## 三、服务器侧

- `server/serve.mjs`：零依赖 Node 静态服务（ETag/CORS/正确 MIME），数据放 `server/data/`
- `analysis/gen-manifest.mjs`：扫描 `plugin/data/*.json` → 算 sha256 → 拷贝到 `server/data/` + 生成 manifest.json
- 加新书流程：本地跑 analysis 管线 → `node gen-manifest.mjs` → 把 `server/` 目录拷到服务器（RDP/WinSCP）→ 插件端自动发现
- 安全：v1 靠端口+路径隐蔽；后续可加 `?token=` 查询串校验（serve.mjs 已预留）

## 七、日常加书/更新数据（不发版）

```
本地: 跑 analysis 管线生成 plugin/data/{新书}.json
     → node analysis/gen-manifest.mjs（自动拷贝+算哈希+出 manifest）
服务器: 把 server/data/ 下变化的文件拷过去（WinSCP/RDP 剪贴板）
完成。插件端下次启动（TTL 30min 内不查，手动点 ⟳ 立即生效）自动同步
```

## 八、已验证场景（2026-10-22 本地 8300 全链路）

首装静默发现新书 / 内置同版免下载（sha 记账）/ ETag 304 二次检查零流量 / 服务器更新已有书增量同步 / 断网重启缓存恢复、查询完全可用 / 手动按钮"已是最新·服务器不可达"反馈。
踩坑记录：数据 URL 必须内容寻址（?v=版本-sha前缀），否则同版本更新被 HTTP 长缓存命中旧文件。

## 九、持久化端到端验证（2026-10-22 双会话实测）

**结论：下载的数据是用户主目录的真实文件（`~/.utools-novel-characters/`），跨会话/断网/重启/插件升级均持久，关闭项目数据不消失。**

实测脚本 `analysis/test-persist.mjs`（模拟 uTools 两次打开插件，preload 以真实 CJS 插件目录结构加载）：

| 会话 | 场景 | 结果 |
|---|---|---|
| 会话1 | 服务器在线，检查更新 | ✓ 测试书下载落盘 `~/.utools-novel-characters/demo-novel.json`（原子写）+ state.json 记账 |
| 会话2 | **服务器已关** + 全新进程 | ✓ 两本书都在（794人+测试书）、搜索可用；静默检查 TTL 跳过（0请求）、手动检查 offline 静默降级 |

持久性边界说明：
- 缓存目录在用户主目录，**不随插件关闭/重启/uTools 退出消失**，也不随插件升级/重装被清（插件目录会被替换，但缓存在外部）
- 插件升级后内置数据变新而缓存还是旧的：加载顺序缓存优先 → 短暂旧数据，下次服务器 manifest 检查（≤TTL 30min 或手动⟳）即自动对齐覆盖
- 唯一丢失途径：用户手删 `~/.utools-novel-characters/`（此时回退内置快照，重新检查即恢复）
- 已知边界：立绘图片不参与热更新（当前印章内联在 JSON 里随书同步；若未来恢复人物立绘需扩展 manifest 的 images 段）
